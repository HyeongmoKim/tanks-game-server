# Tanks Game Server 부하 테스트 결과

테스트 날짜: 2026-08-28

AWS 리전: 서울 (`ap-northeast-2`)

## 목적

AWS EKS에 배포한 TCP 게임 서버가 동시 접속과 로비 요청을 어느 정도 처리하는지 확인한다.

## 테스트 환경

- Amazon EKS 1.36
- EKS 관리형 노드 그룹 1대
- EC2 `c7i-flex.large`
- Amazon Linux 2023 x86_64
- AWS Network Load Balancer
- 게임 서버 Pod 1개
- PostgreSQL 18.4 Pod 1개
- PostgreSQL EBS gp3 5GiB
- Metrics Server

### 게임 서버 리소스 설정

| 구분 | CPU | 메모리 |
|---|---:|---:|
| Request | 250m | 256Mi |
| Limit | 1 core | 768Mi |

### PostgreSQL 리소스 설정

| 구분 | CPU | 메모리 |
|---|---:|---:|
| Request | 200m | 256Mi |
| Limit | 1 core | 1Gi |

## 테스트 시나리오

각 가상 클라이언트는 다음 작업을 수행했다.

1. 외부 NLB의 TCP 7777 포트에 연결
2. 고유한 ID로 로그인
3. 로그인 과정에서 PostgreSQL 플레이어 조회 또는 생성
4. 연결을 유지하며 1초마다 `list_rooms` 요청
5. 서버의 `room_list` 응답 확인

클라이언트 연결은 한꺼번에 생성하지 않고 클라이언트마다 20ms 간격으로 점진적으로 생성했다.

## 결과

| 동시 클라이언트 | 시간 | 성공 요청 | 실패 | 처리량 | p50 | p95 | p99 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 20 | 30초 | 599 | 0 | 19.96 req/s | 12.04ms | 16.52ms | 17.97ms |
| 100 | 60초 | 5,832 | 0 | 97.17 req/s | 12.40ms | 15.39ms | 22.81ms |
| 300 | 60초 | 16,942 | 0 | 282.25 req/s | 12.20ms | 15.42ms | 19.49ms |
| 1,000 | 90초 | 78,606 | 0 | 873.17 req/s | 12.39ms | 16.57ms | 83.62ms |

모든 단계에서 연결과 로그인이 전부 성공했으며 게임 서버와 PostgreSQL Pod의 재시작은 발생하지 않았다.

## 테스트 직후 리소스 사용량

아래 값은 Metrics Server로 테스트 종료 직후 측정한 순간값이며 테스트 중 최대 사용량은 아니다.

| 동시 클라이언트 | 서버 CPU | 서버 메모리 | DB CPU | DB 메모리 |

## 해석

- 1,000개의 동시 TCP 연결에서 요청 실패 없이 약 873 req/s를 처리했다.
- p50과 p95 지연 시간은 부하 증가에도 비교적 일정하게 유지됐다.
- 1,000명 단계에서 p99가 83.62ms로 증가해 일부 요청에서 꼬리 지연이 나타났다.
- 테스트 범위에서는 CPU와 메모리 제한에 도달하지 않았다.
- 이번 결과는 측정한 범위의 결과이며 서버의 최대 처리 한계를 의미하지 않는다.

## 제한 사항

- 각 부하 단계는 한 번씩만 실행했다.
- 한 대의 로컬 컴퓨터에서 인터넷을 통해 부하를 생성했다.
- 로비 조회 중심의 테스트이며 실제 전투 패킷과 다수 사용자 방송은 포함하지 않았다.
- Metrics Server 측정값은 테스트 중 최대값이 아닌 종료 직후의 순간값이다.
- 개발 환경은 단일 워커 노드와 단일 게임 서버 Pod로 구성됐다.

## 향후 개선

- 테스트 중 5초 간격으로 CPU와 메모리 기록
- 30분 이상의 지속 부하 테스트
- 방 생성, 입장, 이동과 발사 패킷 시나리오 추가
- 여러 부하 생성기에서 분산 테스트
- 목표 p95 지연 시간과 허용 오류율 정의
- 병목이 확인된 뒤 수평 또는 수직 확장 검증
